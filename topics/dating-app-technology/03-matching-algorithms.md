# Dating App Technology: Matching Algorithms & Recommendation Systems

## 1. Evolution of Matching Approaches

### Generation 1: Questionnaire-Based (2000s)
- **eHarmony (2000)**: Regression-based matching on variables believed to predict long-term relationship satisfaction. Users answered up to 450 questions. Relied on psychology research to select compatibility variables.
- **OkCupid (2004)**: "Match percentages" computed from user-answered questions and stated importance weights ("irrelevant," "a little," "somewhat," "very"). Transparent and user-controllable.

### Generation 2: Behavioral / Swipe-Based (2012+)
- **Tinder (2012)**: Introduced the swipe paradigm. Moved from explicit questionnaires to implicit behavioral signals. Initially used Elo scores, then evolved to TinVec embeddings.
- **Key shift**: Instead of asking users what they want, observe what they actually do.

### Generation 3: AI-Native (2024+)
- **Deep learning models** combining multiple data modalities (photos, text, behavior, social graph)
- **Vector embeddings** for semantic matching
- **Reinforcement learning** for continuous optimization
- **LLM-powered** profile analysis and conversation coaching

## 2. Core Algorithmic Approaches

### A. Collaborative Filtering

**How it works**: Identifies users with similar behavioral patterns (swipe history) and recommends profiles that similar users liked. If User A and User B both swipe right on the same profiles, the algorithm assumes they have similar tastes and cross-recommends.

**Technical details**:
- Users and items are represented in a user-item interaction matrix
- Matrix factorization (SVD, ALS) decomposes this into latent factor vectors
- Similar users are found via cosine similarity or Euclidean distance in the latent space
- Predictions are generated by finding nearest neighbors

**Key constraint in dating**: Recommendations must be **reciprocal** -- unlike movies, both parties must find each other attractive. This requires bidirectional attraction prediction.

**Advantages**:
- Works without explicit feature engineering -- discovers preferences automatically
- Captures subconscious preferences users cannot articulate
- Profile-agnostic: works regardless of why people prefer someone

**Limitations**:
- **Cold-start problem**: Cannot recommend for new users with no swipe history
- **Popularity bias**: Over-recommends popular profiles
- **Echo chambers**: Reinforces existing preferences, reduces diversity
- **Bias amplification**: Early/majority users disproportionately influence recommendations for minorities
- **Sparsity**: User-item matrices are extremely sparse in dating

### B. Content-Based Filtering

**How it works**: Matches users based on profile attributes -- age, location, interests, education, bio keywords, photo features.

**Technical details**:
- User profiles encoded as feature vectors (TF-IDF for text, CNN features for photos)
- Similarity computed between user preference profiles and candidate profiles
- Can use NLP to analyze bio text for personality traits, interests, communication style

**Advantages**:
- No cold-start problem for items (new profiles can be recommended immediately)
- Transparent and explainable
- Works for niche preferences not well-represented in collaborative data

**Limitations**:
- Over-specialization: only recommends similar profiles
- Requires domain knowledge for feature engineering
- Cannot capture the "chemistry" beyond measurable attributes

### C. Hybrid Approaches (Industry Standard)

**How it works**: Combines collaborative and content-based filtering to leverage strengths and mitigate weaknesses.

**Implementation strategies**:

1. **Weighted Hybrid**: Run both methods independently, combine scores with learned weights
2. **Cascade**: Content-based generates candidates, collaborative re-ranks them
3. **Feature Augmentation**: Collaborative signals become features for content-based model
4. **Meta-Learning**: A meta-model learns when to trust which sub-model

**Why hybrid dominates dating**:
- Content-based handles cold-start (new users matched on profile attributes)
- Collaborative signals phase in as interaction data accumulates
- Addresses the sparsity problem inherent in dating data (much sparser than Netflix/Amazon)

### D. Deep Learning Approaches

**Neural Collaborative Filtering**: Replaces matrix factorization with neural networks, learning non-linear user-item interactions.

**Autoencoders**: Learn compressed representations of user profiles and behaviors, enabling latent similarity matching.

**Graph Neural Networks**: Model the social/interaction graph, learning from the structure of who likes whom.

**Transformer-based**: Process sequences of swipe actions as "sentences," predicting next-likely-liked profiles.

## 3. Real-World Algorithm Implementations

### Tinder: TinVec + Elo (Historical) + VecTec

**Elo Score (Historical, pre-2019)**:
- Adapted from chess rating system (invented by Arpad Elo)
- Single numerical "desirability score" per user
- A right swipe from a high-Elo user boosted your score more than from a low-Elo user
- Created tiered dating market: top ~20% of male profiles got most visibility
- Officially deprecated in 2019, but experts believe a similar scoring system persists

**TinVec (Current)**:
- Developed by Dr. Steve Liu (Tinder's Chief Scientist), presented at MLconf 2017
- Users divided into "Swipers" and "Swipees"
- Each swipee mapped to an embedded vector representing implicit characteristics (activities, interests, career, lifestyle)
- Uses **Word2Vec-inspired skip-gram** architecture:
  - Window size of 5
  - Embedding dimension of 200
  - 50 training epochs
  - Negative sampling (n=5)
- "Rater's taste" computed as the mean embedding of users they liked
- Euclidean distance between rater and ratee embeddings expresses dissimilarity
- Co-liked users end up with similar vectors (analogous to words appearing in similar contexts)
- ROC AUC of 87% and accuracy of 86% demonstrated on like/pass prediction

**VecTec**: Current ML recommendation system combining TinVec user embeddings with additional signals.

**Word2Vec Integration**: While TinVec produces user embeddings from co-swipe patterns, Word2Vec analyzes language patterns in bios and messages.

**Smart Photos**: Uses the Epsilon Greedy algorithm to A/B test photo ordering, maximizing match rates.

### Hinge: Gale-Shapley + ML

**Gale-Shapley Algorithm (1962)**:
- Nobel Prize-winning algorithm solving the "stable marriage problem"
- Creates stable matches where no two individuals would prefer each other over their assigned partner
- Hinge adapts it for the "Most Compatible" feature: one daily top recommendation

**How Hinge adapts Gale-Shapley**:
- ML model infers how each user would rank every other user, based on 24 hours of behavioral data
- For non-heterosexual users, uses the "stable roommate problem" variant (no gender-based partitioning)
- Refreshed every 24 hours based on latest behavioral signals
- Users 8x more likely to go on dates with "Most Compatible" matches than other recommendations

**"We Met" Feedback Loop (2018)**:
- Users report whether they actually met and the quality of the connection
- This real-world outcome data trains the algorithm on what predicts offline success
- Closes the critical feedback gap between in-app behavior and real-world results

**Dealbreakers**: Hard constraints that filter before the algorithm runs (e.g., height, religion, distance).

### Coffee Meets Bagel: Deep Neural Network Ensemble

**Architecture**:
- 9 separate models independently score each potential match
- Scores are converged into a single compatibility rating
- "Blended method" ensemble approach

**Input signals**:
- Profile data (age, location, education, work, preferences)
- Behavioral signals (likes, passes, message response rates)
- Social graph (mutual Facebook/Instagram connections)
- User-set "must-haves" treated as hard filters

**Delivery model**: Gendered -- men receive up to 21 "bagels"/day; women receive up to 6 curated from those who expressed interest.

### Bumble: AI Concierge "Bee" (2026)

- Moving beyond swipes to "chapter-based profiles"
- AI assistant "Bee" learns user values, goals, communication style through conversation
- Rebuilt on cloud-native, AI-enabled architecture from scratch
- Pilot phase as of early 2026; full launch targeted Q2 2026

## 4. Desirability Scoring Mechanisms

### The Elo System (Tinder, Historical)

**How it worked**:
1. Every user assigned a numerical "desirability" score
2. Swiping right on a high-Elo user who swipes right back boosts both scores
3. Being rejected by a high-Elo user decreases your score
4. Indiscriminate right-swiping penalizes your score (signals bot behavior)
5. High-Elo users shown to other high-Elo users (positive feedback loop)

**Problems**:
- Created a stratified dating market where most users had low visibility
- Self-reinforcing: popular profiles became more popular
- Controversial perception of quantifying human "attractiveness"
- Officially retired 2019, but functionally similar systems likely persist

### Modern Desirability Signals

Modern systems use multi-dimensional scoring rather than a single number:
- **Engagement quality**: Response rates, conversation depth, message length
- **Profile completeness**: Filled-out prompts, multiple photos, verified identity
- **Behavioral health**: Selective swiping, consistent usage patterns
- **Reciprocity signals**: How often your likes are reciprocated
- **Activity freshness**: Recent login, profile updates

## 5. Key Technical Challenges in Dating Recommendation

### The Reciprocity Problem
Unlike product recommendations, both users must find each other attractive. This doubles the prediction difficulty -- the algorithm must predict P(A likes B) AND P(B likes A).

### Feedback Loop / Echo Chamber
Collaborative filtering creates self-reinforcing preference loops, reducing diversity and potentially amplifying racial and gender biases. Early/majority users have outsized influence on what later users see.

### Measuring Success
- Matches are not success (many matches never message)
- Messages are not success (many conversations die)
- Phone number exchanges are better but still imperfect
- Real-world dates are closest but hardest to measure
- Hinge's "We Met" feature is the gold standard for closing this loop

### The Explore-Exploit Tradeoff
- **Exploit**: Show users more of what they have historically liked (safe, higher short-term engagement)
- **Explore**: Introduce diverse profiles the user might not have seen (risky, but prevents staleness and bias)
- Typically handled via epsilon-greedy, Thompson sampling, or upper confidence bound methods
